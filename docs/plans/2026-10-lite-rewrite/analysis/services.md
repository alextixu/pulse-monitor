# services

## summary
The app-orchestration subsystem is the glue between Avalonia and the hardware/battery/RGB backends. Program.Main (src/Pulse.App/Program.cs:19-64) parses AppOptions, builds a LoggerFactory with a custom FileLoggerProvider, installs UnhandledException/ProcessExit/UnobservedTaskException hooks that restore fans on abnormal exit, handles `--quit` via SingleInstance.RequestQuit, acquires the Global\Pulse.SingleInstance mutex (10 s wait for `--elevated-relaunch`, otherwise 0), then starts the Avalonia classic desktop lifetime. App.axaml.cs builds a Microsoft.Extensions.DependencyInjection container (App.axaml.cs:235-295) with singletons for ISettingsStore→AppSettings→SettingsService, platform backends (Windows: WindowsPlatformServices, Logitech HID++, ASUS ROG, LibreHardwareMonitor, OpenRGB; demo: fake providers), TrayIconRenderer, MonitoringService, FanModeService, TelemetryLogger, all tab ViewModels, MainViewModel and TrayService; Startup (114-183) applies the theme, saves defaults on first run, optionally relaunches elevated, creates the PopoverWindow, resolves FanModeService before starting MonitoringService, starts TelemetryLogger (never in demo), creates the tray icon, wires SingleInstance show/quit callbacks to the Dispatcher, and shows the popover unless `--minimized`. MonitoringService (MonitoringService.cs) runs two PeriodicTimer loops on the thread pool — batteries every clamp(BatteryRefreshSeconds,5,86400) s (default 30) and hardware every 1 s when TelemetryEnabled (default true) else clamp(HardwareRefreshSeconds,1,3600) — polls every IBatteryProvider in parallel with a 20 s per-provider timeout and the IHardwareMonitor with a 10 s timeout, and publishes everything on Dispatcher.UIThread as ObservableObject properties plus HardwareUpdated/BatteriesUpdated/SummaryChanged events; Publish() derives VisibleBatteries (HiddenDeviceIds filter), LowestBattery and a TraySummary that is value-compared at whole-percent/degree precision so SummaryChanged only fires on visible change. FanModeService subscribes to HardwareUpdated/HardwareStatus/settings changes on the UI thread, feeds the FanPresenceTracker, snapshots FanControlSettings+presence and runs FanModeController.UpdateAsync single-flight (latest request wins) on the pool, posting FanModeResult back to the UI thread; StopApplying/Dispose stop writes before IHardwareMonitor.Dispose hands fans back (DI reverse-order disposal). TelemetryLogger turns every hardware snapshot (while TelemetryEnabled) into one CSV row through a bounded(120, drop-oldest) channel and a single writer task, fixing the column set after 4 warm-up samples and rotating hourly to telemetry-previous.csv. TrayService owns the Avalonia TrayIcon/NativeMenu, debounces icon+tooltip updates by 400 ms (DispatcherTimer), builds TrayIconContent via the pure TrayIconRenderer.Build and renders 32 px PNGs with SkiaSharp wrapped in WindowIcon, now cached per content (uncommitted change) because fresh WindowIcons leaked GDI/USER handles until the 10 000-object quota was hit after ~29 h. SettingsService owns the single shared mutable AppSettings instance, raises Changed(name) on the UI thread and persists via JsonSettingsStore (atomic temp-file write to %APPDATA%\Pulse\settings.json) with a 500 ms DispatcherTimer debounce and a flush on dispose. Logging goes to %LOCALAPPDATA%\Pulse\logs\app.log (2 MiB roll to app.1.log, open/close per line) at Information (Debug for "Pulse.*" only in DEBUG builds) plus the Debug (OutputDebugString) sink. The only UI-free files are AppOptions, JsonSettingsStore, FileLoggerProvider, AppLogging, SingleInstance and TelemetryLogger (the latter only by convention relying on UI-thread event delivery); everything else depends on Avalonia Dispatcher/DispatcherTimer, ObservableObject, TrayIcon/WindowIcon or the ViewModels. There is no test project in the repository.

## wasteFound
- Always-on 1 s hardware polling driven by the TelemetryEnabled default (MonitoringService.cs:296-297, AppSettings.cs:71): every second the full LHM sensor tree is refreshed, published to the UI thread, fed through FanModeController, serialised to CSV and (in CPU tray modes) re-rendered as a tray icon — the dominant steady-state cost of the process. Impact: ~1 full pipeline pass per second even with the popover hidden; halving the cadence halves it.
- Three Dispatcher posts per hardware tick (MonitoringService.cs:393,400,420) and two per battery tick (:315,:341) for IsRefreshing* spinner flags nobody sees while minimized; each post allocates a closure and wakes the UI thread. Impact: ~3 UI wakeups/s plus the Publish work; also 1 post/s while the monitor is Failed/Unsupported because the finally still runs (:418-421).
- Redundant thread-pool hops and per-poll allocations: Task.Run around already-async GetSnapshotAsync (MonitoringService.cs:396) and GetDevicesAsync (:352), plus a linked CancellationTokenSource + CancelAfter timer per poll (:348-349,:394-395). Impact: small (a few hundred bytes + a timer per second) but pointless in a dedicated agent thread.
- FanModeService.Schedule re-copies settings and presence every tick (FanModeService.cs:130): FanControlSettings.From builds 3 HashSets (FanModeController.cs:19-26) and Presence.Capture 2 dictionaries (FanGroupPolicy.cs:117-127); UpdateAsync then allocates a statuses dictionary + one FanModeFanStatus per fan and a FanModeResult every second even in Individual mode with nothing to write (FanModeController.cs:141-337). Impact: ~1–3 KB/s garbage and a thread-pool task per second; cache the settings copy until Changed fires and skip evaluation when mode is Individual with no orphaned/held fans.
- TelemetryLogger per-row cost (TelemetryLogger.cs:150-154,196,205,212): every fan/temperature/storage column does a linear FirstOrDefault over the snapshot list → O(columns × items) per row (≈500–1000 string compares with ~10 fans/15 temps), ~60–100 transient strings per row, and AutoFlush=true forces one write syscall per second (:113,:139). Impact: minor CPU, 1 disk write/s; precompute per-row index maps and flush every few seconds instead. The 120-deep queue also pins up to 120 HardwareSnapshot+FanModeResult graphs under backpressure (:25-26,:242).
- Tray icon updates in CpuLoad/CpuTemperature modes change content nearly every second → Shell_NotifyIcon modify + Avalonia PNG→HICON conversion each time (TrayService.cs:81-86, TrayIconRenderer.cs:108-126); the new cache stops re-rendering but keeps every distinct WindowIcon (≈100–300 realistic, up to 1024) and its native handles alive for the process lifetime (TrayIconRenderer.cs:102-105). BuildTooltip re-formats all lines on every update (TrayService.cs:102-119). Impact: ~1 tray update/s + a few hundred permanently pinned GDI/USER objects; a GDI implementation with DestroyIcon needs no cache.
- FileLoggerProvider.Write stats, opens, appends and closes the log file for every line under a global lock (FileLoggerProvider.cs:44-57,60-63). Impact: negligible at the Information steady state (~2–5 lines/min) but 3–4 syscalls per line during Debug/warning bursts; a persistent StreamWriter with flush-on-write is cheaper and avoids the roll race between two processes.
- AppLogging.AddDebug() is unconditional (AppLogging.cs:18): every log line is also sent through OutputDebugString in Release. Impact: one extra kernel call per line; remove in Release.
- LogBatteries builds the full signature string via string.Join + interpolation on every battery poll even when nothing changed (MonitoringService.cs:463). Impact: trivial at 30 s cadence.
- All tab ViewModels are singletons created at startup and subscribed to MonitoringService even when started --minimized (App.axaml.cs:146,286-291; DevicesViewModel.cs:30-31, SystemViewModel.cs:56-59, FansViewModel.cs:82-84, LightingViewModel.cs:55-57, MainViewModel.cs:82-83): every LatestHardware/HardwareStatus/VisibleBatteries change rebuilds observable collections for a hidden window. Impact: the largest avoidable UI-thread work per tick; the process split removes it entirely.
- Avalonia + Skia + Fluent theme + Inter font are loaded for a tray-only resident (Program.cs:67-71, csproj:30-35) — tens of MB of working set and startup time for a process that spends >99% of its life hidden. Impact: the primary motivation for the headless agent.
- PeriodicTimer.Period is re-read and conditionally reassigned every tick (MonitoringService.cs:260-261,281-282) — negligible, but a settings change from a long period to a short one is delayed by up to the old period; Changed-driven timer reset would be both cheaper and more responsive.
- SingleInstance calls WindowsIdentity.GetCurrent() three times (mutex + 2 events) at startup (SingleInstance.cs:132,144,158-162) — startup-only, negligible.
- Cosmetic: tooltip truncation cuts at '\n' so the kept text ends with the preceding '\r' before "…" (TrayService.cs:122-123) — produces "...\r…"; cut one character earlier when the line separator is "\r\n".
