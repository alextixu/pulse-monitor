# platform

## summary
The "platform glue / build / install / docs" layer of Pulse is small and almost entirely Avalonia-free, which makes it the easiest part to carry into a headless agent. src/Pulse.Windows contains two battery providers (WinRT Bluetooth, GetSystemPowerStatus system battery), the UAC relaunch service and the HKCU Run-key auto-start service, all registered as singletons by AddWindowsPlatformServices() (WindowsServiceCollectionExtensions.cs:12-19) and consumed by App.axaml.cs:268 only when !Demo && IsWindows. Pulse.exe is the only executable: Pulse.App.csproj (AssemblyName Pulse, OutputType WinExe, TFM net9.0-windows10.0.19041.0, asInvoker manifest) hosts Program.Main, which parses --minimized/--elevated-relaunch/--demo/--screenshot/--quit (AppOptions.cs:30-48), handles --quit via Global named events (SingleInstance.cs:79-108) before any Avalonia code runs, acquires the Global\Pulse.SingleInstance mutex (waiting up to 10 s when --elevated-relaunch), and only then starts Avalonia. Elevation is opt-in: the manifest stays asInvoker (app.manifest:10) and App.Startup relaunches via ShellExecute "runas" when settings.RequestElevationOnStartup is set or the user clicks the banner, appending --elevated-relaunch so the new instance never relaunches again (WindowsElevationService.cs:30-81, App.axaml.cs:133-144). Auto-start has two unrelated mechanisms: the in-app toggle writes HKCU\...\Run\Pulse = "<exe>" --minimized (unelevated, and redirected into the Claude MSIX LocalCache when launched from Claude's shell per the user's memory), while the recommended path is tools/install-pulse.ps1, which registers Task Scheduler task "Pulse" running publish\win-x64\Pulse.exe --minimized at logon with RunLevel Highest, no time limit, restart 3x/1 min, IgnoreNew; the live task XML confirms exactly that configuration. OpenRGB is bundled as a separate GPL program: fetch-openrgb.ps1 stages third_party\OpenRGB (gitignored) and Pulse.App.csproj:24-28 copies it plus NOTICE/GPL text to <out>\OpenRGB\, which OpenRgbServerLauncher resolves relative to AppContext.BaseDirectory (OpenRgbServerLauncher.cs:45-49) — so the OpenRGB folder must sit next to whichever exe hosts Pulse.Rgb (the agent). The publish folder is framework-dependent (runtimeconfig names Microsoft.NETCore.App 9.0.0; no coreclr/hostfxr/hostpolicy), 105.1 MB / 94 files: 48.6 MB is OpenRGB+Qt, and of the 56.5 MB Pulse payload 24.2 MB (43%) is the CsWinRT Windows SDK projection pulled in solely for WindowsBluetoothBatteryProvider, 14.1 MB Avalonia (incl. 5.2 MB ANGLE, 1.8 MB Inter font, ~1.1 MB Linux/macOS backends), 11.2 MB Skia/HarfBuzz natives, 4.6 MB LibreHardwareMonitor and its deps, and only 1.4 MB of Pulse's own code. No lean-build flags exist anywhere (no trimming, R2R, InvariantGlobalization, GC settings); Directory.Build.props sets only nullable-as-error, NoWarn CA1416, SatelliteResourceLanguages=en and Version 0.1.0. The README (372 lines, Traditional Chinese) documents the in-process architecture in detail — Dispatcher.UIThread.Post publishing, Skia-drawn Avalonia TrayIcon, single-instance "show popover" semantics, the UI-triggered elevated relaunch — and roughly a dozen sections will become false after the agent/UI split, while the install/update instructions stay valid as long as the agent keeps the name Pulse.exe in publish\win-x64 and accepts --minimized and --quit.
